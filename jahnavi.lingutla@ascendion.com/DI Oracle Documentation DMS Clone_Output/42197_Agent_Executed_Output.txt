# Oracle Stored Procedure Documentation

## Procedure Name
**bronze.usp_Load_bronze_Layer_Full**

## Overview
This is a master orchestration stored procedure that executes a full refresh ETL pipeline for the bronze layer. It sequentially loads 12 different tables from source to bronze layer and maintains comprehensive audit logging for the entire process.

## Schema
**bronze**

## Procedure Type
**Orchestration/Master Procedure**

## Parameters
**None** - This procedure does not accept any input parameters.

## Purpose
Orchestrates the complete bronze layer ETL pipeline by:
- Executing individual table load procedures in sequence
- Generating a unique batch ID for tracking
- Collecting and aggregating execution statistics
- Logging comprehensive audit information
- Handling errors and maintaining data integrity

## Process Flow

### 1. Initialization Phase
- Generates unique Batch ID using timestamp format: 'YYYY-MM-DD HH24:MI:SS.FF3'
- Logs pipeline start information including:
  - Start timestamp
  - Executing user
  - Batch ID

### 2. Table Loading Phase
Sequentially executes 12 table load procedures:

| Sequence | Procedure Name | Target Table | Notes |
|----------|---------------|--------------|-------|
| 1 | bronze.usp_Load_bz_New_Monthly_HC_Report | bz_New_Monthly_HC_Report | - |
| 2 | bronze.usp_Load_bz_SchTask | bz_SchTask | Excludes TIMESTAMP column |
| 3 | bronze.usp_Load_bz_Hiring_Initiator_Project_Info | bz_Hiring_Initiator_Project_Info | - |
| 4 | bronze.usp_Load_bz_Timesheet_New | bz_Timesheet_New | - |
| 5 | bronze.usp_Load_bz_report_392_all | bz_report_392_all | - |
| 6 | bronze.usp_Load_bz_vw_billing_timesheet_daywise_ne | bz_vw_billing_timesheet_daywise_ne | - |
| 7 | bronze.usp_Load_bz_vw_consultant_timesheet_daywise | bz_vw_consultant_timesheet_daywise | - |
| 8 | bronze.usp_Load_bz_DimDate | bz_DimDate | - |
| 9 | bronze.usp_Load_bz_holidays_Mexico | bz_holidays_Mexico | - |
| 10 | bronze.usp_Load_bz_holidays_Canada | bz_holidays_Canada | - |
| 11 | bronze.usp_Load_bz_holidays | bz_holidays | - |
| 12 | bronze.usp_Load_bz_holidays_India | bz_holidays_India | - |

Each procedure call:
- Receives the batch ID as parameter
- Increments the v_TablesProcessed counter
- Logs its own execution details to bronze.bz_Audit_Log

### 3. Statistics Aggregation Phase
Queries the audit log table to calculate:

**Success Metrics:**
```sql
SELECT COUNT(*), NVL(SUM(records_inserted), 0)
FROM bronze.bz_Audit_Log
WHERE batch_id = v_BatchID AND status = 'SUCCESS'
```

**Failure Metrics:**
```sql
SELECT COUNT(*), NVL(SUM(records_failed), 0)
FROM bronze.bz_Audit_Log
WHERE batch_id = v_BatchID AND status = 'FAILED'
```

**Calculated Metrics:**
- v_TotalRowsProcessed = v_TotalRowsInserted + v_TotalRowsFailed
- Execution time calculated using EXTRACT functions on timestamp difference

### 4. Completion Logging Phase
Outputs comprehensive summary including:
- End timestamp
- Total execution time (seconds)
- Tables processed/succeeded/failed counts
- Row counts (inserted/failed)

### 5. Master Audit Record Creation
Inserts a master audit record into bronze.bz_Audit_Log with:
- Source: 'source_layer.*'
- Target: 'bronze.*'
- Load type: 'FULL_REFRESH_ALL_TABLES'
- All aggregated statistics
- Batch ID for correlation

### 6. Transaction Commit
Commits all changes to persist audit records.

## Error Handling

### Exception Block
When any error occurs:

1. **Error Capture:**
   - Error message (SQLERRM)
   - Error number (SQLCODE)
   - Sets error severity, state, and line (initialized to 0)

2. **Timing Calculation:**
   - Calculates execution time up to point of failure
   - Sets overall status to 'FAILED'

3. **Error Logging:**
   - Outputs detailed error information to DBMS_OUTPUT
   - Includes error number, severity, state, line, and message

4. **Error Audit Record:**
   - Inserts error record into bronze.bz_Audit_Log
   - Includes all error details in error_message field
   - Format: 'Error [error_code]: [error_message]'

5. **Transaction Handling:**
   - Commits the error audit record
   - Re-throws error using RAISE_APPLICATION_ERROR with error code -20001

## Performance Considerations

1. **Sequential Processing:** Tables are loaded sequentially, not in parallel
2. **Single Transaction:** All audit logging is committed at the end
3. **Execution Time:** Depends on cumulative time of all 12 child procedures
4. **Audit Queries:** Two aggregation queries on audit log after all loads complete

## Best Practices Implemented

1. ✅ Comprehensive error handling with detailed logging
2. ✅ Batch ID for tracking related operations
3. ✅ Audit trail for all operations
4. ✅ Execution time tracking
5. ✅ User tracking for accountability
6. ✅ Structured logging with clear delimiters
7. ✅ Transaction management with explicit commits
8. ✅ Error propagation after logging

## Potential Improvements

1. **Parallel Processing:** Consider parallel execution of independent table loads
2. **Retry Logic:** Add retry mechanism for transient failures
3. **Configurable Table List:** Make table list configurable rather than hard-coded
4. **Notification:** Add email/alert notification on failure
5. **Performance Metrics:** Add more detailed performance metrics per table
6. **Rollback Strategy:** Implement rollback mechanism for partial failures
7. **Dynamic SQL:** Use dynamic SQL to make procedure more flexible

## Maintenance Notes

- When adding new tables to bronze layer, add corresponding procedure call in sequence
- Ensure all child procedures accept batch_id parameter
- Ensure all child procedures log to bronze.bz_Audit_Log
- Update v_TablesProcessed counter when adding/removing table loads
- Test error handling after any modifications
